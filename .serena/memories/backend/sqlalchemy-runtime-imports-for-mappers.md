When working with SQLModel/SQLAlchemy relationships in this repo, do not blindly move target-model imports into TYPE_CHECKING blocks. If a model uses string relationship targets or cross-module foreign keys, the related model may need a runtime import so its mapper/table is registered before tests or metadata configuration run. This surfaced in device/workline models: keeping runtime imports in src/app/device/models/device.py, command.py, and event_log.py avoided InvalidRequestError for 'WorkLine' and NoReferencedTableError for wes_biz.work_lines. If Ruff TC001 flags such imports, keep them and document with noqa: TC001 plus a short reason.
