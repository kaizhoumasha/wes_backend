## 1. 接口概览

### 1.1 系统概述

SMT 流水线系统是一个自动化物料输送和扫码识别系统，主要用于 SMT 生产线上料箱的输送和扫码识别。系统包含多个扫码工位、入料工位和出料工位，支持与 WES（仓储执行系统）集成。

### 1.2 系统组成

- 扫码工位: `STATION_SCAN1~16`
- 入料工位: `STATION_INPUT1~4`
- 出料工位: `STATION_OUTPUT1~4`
- 流水线工位: `PIPELINE_INPUT2/4`、`PIPELINE_OUTPUT2/3/4`

### 1.3 接口分类

| 接口类型 | 方向 | 说明 |
| --- | --- | --- |
| 命令接口 | `WES -> 设备` | 发送移动、取消等命令 |
| 查询接口 | `WES -> 设备` | 查询设备状态 |
| 回调接口 | `设备 -> WES` | 任务结果回传、事件推送 |

### 1.4 接口列表

| 序号 | 接口名称 | HTTP 方法 | 端点 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 发送移动命令 | `POST` | `/api/v1/command` | 发送 `MOVE` 命令 |
| 2 | 取消命令 | `POST` | `/api/v1/command/cancel` | 取消正在执行的命令 |
| 3 | 查询设备状态 | `GET` | `/api/v1/status` | 查询所有设备状态 |
| 4 | 任务结果回传 | `POST` | `[WES回调地址]` | 设备向 WES 回传任务结果 |
| 5 | 事件推送 | `POST` | `[WES事件上报地址]` | 设备向 WES 推送事件 |

### 1.5 通信协议

- 协议: `HTTP/1.1`
- 数据格式: `JSON`
- 字符编码: `UTF-8`
- `Content-Type: application/json`

## 2. 数据模型定义

### 2.1 `MoveCommand`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `device_code` | `string` | 是 | 指定执行命令的工位编码 |
| `command_code` | `string` | 是 | 全局唯一命令编码 |
| `timestamp` | `string` | 是 | 毫秒级时间戳 |
| `task_type` | `string` | 是 | 任务类型 |
| `priority` | `number` | 是 | 优先级 `1-10`，`10` 最高 |
| `timeout` | `number` | 是 | 期望完成时间，毫秒 |
| `source` | `object` | 是 | 源位置信息 |

### 2.2 `MoveLocationInfo`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `location_id` | `string` | 是 | 位置 ID |
| `location_type` | `string` | 是 | 工位类型 |
| `bin_id` | `string` | 否 | 箱子 ID，ECS 追溯用 |
| `bin_type` | `string` | 否 | 箱子类型，`三格箱` / `六格箱` |

`location_type` 枚举：

- `SCAN_PLATFORM`: 扫码平台
- `PICK_PLATFORM`: 取料平台
- `PUT_PLATFORM`: 放料平台

### 2.3 `DeviceStatusItem`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `device_code` | `string` | 设备编码 |
| `timestamp` | `number` | 毫秒级时间戳 |
| `current_command_code` | `string` | 当前正在执行的命令编码，空闲时为空 |
| `error_code` | `string` | 错误码，无错误时为 `NONE` |
| `status` | `string` | 设备状态 |

### 2.4 `EventPush`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `device_code` | `string` | 设备编码 |
| `timestamp` | `long` | 事件时间戳 |
| `event_type` | `string` | `BIN_ARRIVED` / `BIN_DEPARTED` / `SCAN_COMPLETED` |
| `data` | `object` | 业务负载数据 |

### 2.5 `EventData`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `location` | `string` | 位置 |
| `LotCode / DateCode / Qty / ProductNo / MfrPN / PONumber` | `string` | 六个一维码字段，仅在 `SCAN_COMPLETED` 时出现 |

### 2.6 `TaskResultReport`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `command_code` | `string` | 必须回传原指令编码 |
| `device_code` | `string` | 设备编码 |
| `result` | `string` | `SUCCESS` / `FAILED` |
| `finish_time` | `long` | 完成时间戳 |
| `data` | `object` | 业务回传数据 |
| `error_detail` | `object` | 错误详情，失败时必填 |

`data` 关键字段：

- `actual_qty`: 实际操作数量
- `result`: `MOVE_FINISHED` / `MOVE_FAILED`

### 2.7 `ApiResult`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | `string` | `SUCCESS` / `FAILED` |
| `message` | `string` | 成功或错误描述 |
| `code` | `string` | `200` / `400` / `503` |
| `trace_id` | `string` | 供应商内部日志 ID |

## 3. 命令接口

### 3.1 发送移动命令

- 接口描述: 向指定流水线工位发送移动命令，控制料箱移动
- HTTP 方法: `POST`
- 请求端点: `/api/v1/command`

请求参数：

| 参数名 | 类型 | 必填 | 说明 | 示例值 |
| --- | --- | --- | --- | --- |
| `device_code` | `string` | 是 | 指定执行命令的工位编码 | `STATION_SCAN1` |
| `command_code` | `string` | 是 | 命令编码，全局唯一 | `CMD-20251215-1001` |
| `timestamp` | `string` | 是 | 毫秒级时间戳 | `1702627300000` |
| `task_type` | `string` | 是 | 任务类型 | `MOVE_FORWARD` |
| `priority` | `number` | 是 | 优先级 | `1` |
| `timeout` | `number` | 是 | 超时时间（ms） | `30000` |
| `source` | `object` | 是 | 源位置信息 | - |

`task_type` 枚举：

- `MOVE_FORWARD`
- `MOVE_BACKWARD`
- `MOVE_LEFT`
- `MOVE_RIGHT`

请求示例：

```json
{
  "device_code": "STATION_SCAN1",
  "command_code": "CMD-20251215-1001",
  "timestamp": "1702627300000",
  "task_type": "MOVE_FORWARD",
  "priority": 1,
  "timeout": 30000,
  "source": {
    "location_id": "STATION_SCAN1",
    "location_type": "SCAN_PLATFORM",
    "bin_id": "BIN_104",
    "bin_type": "三格箱"
  }
}
```

响应说明：

- `message` 枚举值：
  - `Accepted`
  - `Rejected`
  - `Timeout`
  - `DeviceBusy`
  - `DeviceError`

成功响应示例：

```json
{
  "status": "SUCCESS",
  "message": "Accepted",
  "code": "200",
  "trace_id": "DEV-LOG-CMD-20251215-1001"
}
```

失败响应示例：

```json
{
  "status": "FAILED",
  "message": "DeviceBusy",
  "code": "503",
  "trace_id": "DEV-LOG-CMD-20251215-1001"
}
```

### 3.2 取消命令

- 接口描述: 取消正在执行的命令
- HTTP 方法: `POST`
- 请求端点: `/api/v1/command/cancel`

```json
{
  "command_code": "CMD-20251215-1001"
}
```

成功响应示例：

```json
{
  "status": "SUCCESS",
  "message": "Cancelled",
  "code": "200",
  "trace_id": "DEV-LOG-CMD-20251215-1001"
}
```

## 4. 查询接口

### 4.1 查询设备状态

- 接口描述: 查询所有流水线工位的当前状态
- HTTP 方法: `GET`
- 请求端点: `/api/v1/status`
- 请求参数: 无

状态枚举：

- `IDLE`
- `RUNNING`
- `ERROR`
- `PAUSED`
- `STOPPED`
- `OFFLINE`

响应示例：

```json
{
  "status": [
    {
      "device_code": "STATION_SCAN1",
      "timestamp": 1702627300000,
      "current_command_code": "CMD-20251215-1001",
      "error_code": "NONE",
      "status": "RUNNING"
    },
    {
      "device_code": "STATION_INPUT1",
      "timestamp": 1702627300000,
      "current_command_code": "CMD-20251215-1017",
      "error_code": "NONE",
      "status": "RUNNING"
    }
  ]
}
```

设备范围：

- 扫码工位: `STATION_SCAN1~16`
- 入料工位: `STATION_INPUT1~4`
- 出料工位: `STATION_OUTPUT1~4`

## 5. 回调接口

### 5.1 任务结果回传

- 接口描述: 设备完成移动命令后，向 WES 回传任务执行结果
- HTTP 方法: `POST`
- 请求端点: `[WES提供的回调地址]`

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `command_code` | `string` | 是 | 必须回传原指令编码 |
| `device_code` | `string` | 是 | 设备编码 |
| `result` | `string` | 是 | 执行结果，`SUCCESS` / `FAILED` |
| `finish_time` | `number` | 是 | 完成时间戳 |
| `data` | `object` | 否 | 业务回传数据 |
| `error_detail` | `object` | 否 | 失败时必填 |

成功回传示例：

```json
{
  "command_code": "CMD-20251215-1001",
  "device_code": "STATION_SCAN1",
  "result": "SUCCESS",
  "finish_time": 1702627250000,
  "data": {
    "actual_qty": 1,
    "result": "MOVE_FINISHED"
  }
}
```

失败回传示例：

```json
{
  "command_code": "CMD-20251215-1001",
  "device_code": "STATION_SCAN1",
  "result": "FAILED",
  "finish_time": 1702627250000,
  "data": {
    "actual_qty": 0,
    "result": "MOVE_FAILED"
  },
  "error_detail": {
    "error_code": "TARGET_BLOCKED",
    "error_message": "Path blocked"
  }
}
```

WES 响应示例：

```json
{
  "status": "SUCCESS",
  "message": "ACK",
  "code": "200",
  "trace_id": "DEV-LOG-1702627300000"
}
```

### 5.2 事件推送

- 接口描述: 料箱到达、离开或扫码设备完成扫码后，向 WES 推送事件
- HTTP 方法: `POST`
- 请求端点: `[WES提供的回调地址]`

`event_type` 枚举：

- `BIN_ARRIVED`
- `BIN_DEPARTED`
- `SCAN_COMPLETED`

事件示例：

扫码完成：

```json
{
  "device_code": "STATION_SCAN1",
  "event_type": "SCAN_COMPLETED",
  "timestamp": 1702627300000,
  "data": {
    "location": "STATION_SCAN1",
    "LotCode": "SMTLOT20260327001",
    "DateCode": "20260327",
    "Qty": "100",
    "ProductNo": "PN001",
    "MfrPN": "MFR002",
    "PONumber": "PO20260327001"
  }
}
```

扫码失败：

```json
{
  "device_code": "STATION_SCAN1",
  "event_type": "SCAN_COMPLETED",
  "timestamp": 1702627300000,
  "data": {
    "location": "STATION_SCAN1"
  }
}
```

料箱到达：

```json
{
  "device_code": "STATION_INPUT1",
  "event_type": "BIN_ARRIVED",
  "timestamp": 1702627300000,
  "data": {
    "location": "STATION_INPUT1"
  }
}
```

料箱离开：

```json
{
  "device_code": "STATION_OUTPUT1",
  "event_type": "BIN_DEPARTED",
  "timestamp": 1702627300000,
  "data": {
    "location": "STATION_OUTPUT1"
  }
}
```

WES 响应示例：

```json
{
  "status": "SUCCESS",
  "message": "ACK",
  "code": "200",
  "trace_id": "DEV-LOG-1702627300000"
}
```

## 6. 错误处理

### 6.1 HTTP 状态码

| 状态码 | 说明 | 处理建议 |
| --- | --- | --- |
| `200` | 成功 | 正常处理响应数据 |
| `400` | 请求参数错误 | 检查请求参数格式和必填字段 |
| `503` | 设备忙 / 故障 | 等待设备空闲后重试或联系技术支持 |

### 6.2 业务错误码

| code | 说明 | 处理建议 |
| --- | --- | --- |
| `200` | 成功 | - |
| `400` | 参数错误 | 检查参数格式 |
| `503` | 设备忙 | 等待后重试 |

### 6.3 设备错误码

| error_code | 说明 | 处理建议 |
| --- | --- | --- |
| `NONE` | 无错误 | - |
| `TARGET_BLOCKED` | 路径被阻挡 | 清理障碍物后重试 |
| `MOVE_FAILED` | 移动失败 | 检查位置是否可访问 |
| `DEVICE_FAULT` | 设备故障 | 联系技术支持 |
