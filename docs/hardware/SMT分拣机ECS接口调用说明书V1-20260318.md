## 1. 接口概览

### 1.1 接口分类

| 接口类型 | 方向 | 说明 |
| --- | --- | --- |
| 命令接口 | `WES -> 设备` | 发送搬运、取消等命令 |
| 查询接口 | `WES -> 设备` | 查询设备状态 |
| 回调接口 | `设备 -> WES` | 任务结果回传 |
| 事件推送接口 | `设备 -> WES` | 设备事件推送，如扫码完成 |

### 1.2 接口列表

| 序号 | 接口名称 | HTTP 方法 | 端点 | 说明 |
| --- | --- | --- | --- | --- |
| 1 | 发送搬运命令 | `POST` | `/api/v1/command` | 发送 `PICK_AND_PUT` 命令 |
| 2 | 取消命令 | `POST` | `api/v1/device/cancel` | 取消正在执行的命令 |
| 3 | 查询设备状态 | `GET` | `/api/v1/status` | 查询所有设备状态 |
| 4 | 任务结果回传 | `POST` | `[WES回调地址]` | 设备向 WES 回传任务结果 |
| 5 | 事件推送 | `POST` | `[WES事件上报地址]` | 设备向 WES 推送事件 |

### 1.3 通信协议

- 协议: `HTTP/1.1`
- 数据格式: `JSON`
- 字符编码: `UTF-8`
- `Content-Type: application/json`

## 2. 数据模型定义

### 2.1 `PickAndPutCommand`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `device_code` | `string` | 设备编码，`ARM01/ARM02` |
| `command_code` | `string` | 全局唯一命令编码 |
| `timestamp` | `string` | 毫秒级时间戳 |
| `task_type` | `string` | `PICK_AND_PUT` / `SCAN` / `MOVE_FORWARD` / `MOVE_BACKWARD` / `MOVE_LEFT` / `MOVE_RIGHT` |
| `priority` | `string` | 优先级 |
| `timeout` | `string` | 超时时间 |
| `source` | `LocationInfo` | 源库位信息 |
| `target` | `LocationInfo` | 目标库位信息 |

### 2.2 `LocationInfo`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `location_id` | `string` | 位置 ID，如 `STATION_A`、`STATION_B`、`STATION_SCAN`、`STATION_WORK1` |
| `location_type` | `string` | 位置类型 |
| `bin_id` | `string` | 箱子 ID |
| `bin_type` | `string` | 箱子类型，`三格箱/六格箱` |
| `bin_location` | `string` | 箱子位置，`A/B/C/D` |
| `bin_cell_location` | `string` | 箱子单元格位置 |
| `reel_layer` | `string` | 料盘层数 |
| `reel_thickness` | `string` | 料盘厚度，`mm` |
| `reel_totalthickness` | `string` | 料盘总厚度 |
| `reel_diameter` | `string` | 料盘直径，`7寸/13寸/15寸` |
| `rack_id` | `string` | 料架 ID |
| `rack_side` | `string` | 料架面数，`A/B` |
| `rack_layer` | `string` | 料架层数，`1-5` |
| `rack_column` | `string` | 料架列数 |

`location_type` 枚举：

| 值 | 说明 | 可用位置 ID |
| --- | --- | --- |
| `ONE_LAYER_RACK` | 单层货架 | `STATION_A`, `STATION_B` |
| `FIVE_LAYER_RACK` | 五层货架 | `STATION_A`, `STATION_B` |
| `SCAN_PLATFORM` | 扫码平台 | `STATION_SCAN` |
| `SCAN_NG` | NG 平台 | `STATION_NG` |
| `BIN` | 流水线料箱 | `STATION_WORK1` / `STATTION_SCAN1` |

### 2.3 `ApiResult`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | `string` | `SUCCESS` / `FAILED` |
| `message` | `string` | 成功或错误描述 |
| `code` | `string` | `200` / `400` / `503` |
| `trace_id` | `string` | 供应商内部日志 ID |

## 3. 命令接口

### 3.1 发送搬运命令

- 接口描述: 向指定机械臂发送搬运命令，控制机械臂从源位置取料并放到目标位置
- HTTP 方法: `POST`
- 正文请求端点: `http://<DEVICE_IP>:<PORT>/api/v1/device/command`
- 说明: PDF 的接口列表页使用的是 `/api/v1/command`，正文详细页使用的是 `/api/v1/device/command`

请求参数：

| 参数名 | 类型 | 必填 | 说明 | 示例值 |
| --- | --- | --- | --- | --- |
| `device_code` | `string` | 是 | 执行命令的机械臂编码 | `ARM01` / `ARM02` |
| `command_code` | `string` | 是 | 全局唯一命令编码 | `CMD-20251215-1001` |
| `timestamp` | `string` | 是 | 毫秒级时间戳 | `1702627300000` |
| `task_type` | `string` | 是 | 任务类型 | `PICK_AND_PUT` |
| `priority` | `number` | 是 | 优先级 | `1` |
| `timeout` | `number` | 是 | 期望完成时间（ms） | `30000` |
| `source` | `object` | 是 | 源库位信息 | - |
| `target` | `object` | 是 | 目标库位信息 | - |

`task_type` 枚举：

- `PICK_AND_PUT`
- `SCAN`
- `MOVE_FORWARD`
- `MOVE_BACKWARD`
- `MOVE_LEFT`
- `MOVE_RIGHT`

## 5. 回调接口

### 5.1 任务结果回传

- 接口描述: 设备完成搬运命令后，向 WES 回传任务执行结果
- HTTP 方法: `POST`
- 请求端点: `http://<WES_IP>:<PORT>/api/v1/callback/result]`

说明：原 PDF 这里多了一个右方括号 `]`，已按原文保留。

请求参数：

| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `command_code` | `string` | 是 | 必须回传原指令编码 |
| `device_code` | `string` | 是 | 设备编码，如 `ARM_01` |
| `result` | `string` | 是 | `SUCCESS` / `FAILED` |
| `finish_time` | `number` | 是 | 完成时间戳 |
| `data` | `object` | 否 | 业务回传数据 |
| `error_detail` | `object` | 否 | 失败详情 |

`pick_and_put_result` 枚举：

- `PUT_FINISHED`
- `PUT_FAILED`
- `PICK_FAILED`

成功回传示例：

```json
{
  "command_code": "CMD-20251215-1001",
  "device_code": "ARM_01",
  "result": "SUCCESS",
  "finish_time": 1702627250000,
  "data": {
    "actual_qty": 1,
    "pick_and_put_result": "PUT_FINISHED"
  }
}
```

失败回传示例：

```json
{
  "command_code": "CMD-20251215-1001",
  "device_code": "ARM_01",
  "result": "FAILED",
  "finish_time": 1702627250000,
  "data": {
    "actual_qty": 0,
    "pick_and_put_result": "PUT_FAILED"
  },
  "error_detail": {
    "error_code": "1001",
    "error_message": "Target position blocked"
  }
}
```

WES 响应示例：

```json
{
  "status": "SUCCESS",
  "message": "ACK",
  "code": "200",
  "trace_id": "DEV-LOG-1702627300000"
}
```

### 5.2 事件推送

- 接口描述: 扫码设备完成扫码后，向 WES 推送扫码事件
- HTTP 方法: `POST`
- 请求端点: `[http://<WES_IP>:<PORT>/api/v1/callback/event]`

`event_type` 枚举：

- `SCAN_COMPLETED`
- `ESTOP_PRESSED`

## 6. 错误处理

### 6.1 HTTP 状态码

| 状态码 | 说明 | 处理建议 |
| --- | --- | --- |
| `200` | 成功 | 正常处理响应数据 |
| `400` | 请求参数错误 | 检查请求参数格式和必填字段 |
| `503` | 设备忙 / 故障 | 等待设备空闲后重试或联系技术支持 |

### 6.2 业务错误码

| code | 说明 | 处理建议 |
| --- | --- | --- |
| `200` | 成功 | - |
| `400` | 参数错误 | 检查参数格式 |
| `503` | 设备忙 | 等待后重试 |

### 6.3 设备错误码

> **历史错误码说明**：下表保留的是该版 ECS 文档中的**历史供应商数字码**，仅用于对照旧协议与定位历史偏差；当前插件体系已统一消费标准语义错误码，例如 `TARGET_BLOCKED` / `PICK_FAILED` / `PLACE_FAILED`，而不是直接消费这些数字码。

| error_code | 说明 | 处理建议 |
| --- | --- | --- |
| `NONE` | 无错误 | - |
| `1001` | 目标位置被阻挡 | 清理障碍物后重试 |
| `1002` | 取料失败 | 检查物料位置是否正确 |
| `1003` | 放料失败 | 检查目标位置是否可访问 |
