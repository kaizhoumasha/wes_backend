## 1. 接口概览

### 1.1 接口分类

| 接口类型     | 方向        | 说明                                |
| ------------ | ----------- | ----------------------------------- |
| 命令接口     | WES → 设备 | 发送搬运、取消等命令                |
| 查询接口     | WES → 设备 | 查询设备状态                        |
| 回调接口     | 设备 → WES | 任务结果回传、                      |
| 事件推送接口 | 设备 → WES | 设备事件推送 设备状态变化如扫码完成 |

### 1.2 接口列表

| 序号 | 接口名称     | HTTP方法 | 端点                 | 说明                  |
| ---- | ------------ | -------- | -------------------- | --------------------- |
| 1    | 发送搬运命令 | POST     | /api/v1/device/command      | 发送PICK_AND_PUT命令  |
| 2    | 取消命令     | POST     | /api/v1/device/cancel | 取消正在执行的命令    |
| 3    | 查询设备状态 | GET      | /api/v1/device/status       | 查询所有设备状态      |
| 4    | 任务结果回传 | POST     | [WES回调地址]        | 设备向WES回传任务结果 |
| 5    | 事件推送     | POST     | [WES事件上报地址]    | 设备向WES推送事件     |

### 1.3 通信协议

- **协议**: HTTP/1.1
- **数据格式**: JSON
- **字符编码**: UTF-8
- **Content-Type**: application/json

### 1.4 安全认证

ECS调用WES接口使用 **app_id/app_secret** 签名认证方式，区别于WEB操作使用的Bearer Token认证：

| 认证方式                    | 适用场景             | 说明                                 |
| --------------------------- | -------------------- | ------------------------------------ |
| **app_id/app_secret** | 设备操作（ECS→WES） | HMAC-SHA256签名，设备端调用WES接口   |
| **Bearer Token**      | WEB操作              | Token认证，由WES项目组在联调阶段分配 |

**签名认证流程**：`HMAC-SHA256(app_id + timestamp + method + path, app_secret)`
请求头携带：`X-App-ID`、`X-Timestamp`、`X-Signature`

**WES认证服务**：`https://mcs.happytable.cc/login`
**默认凭证**（联调阶段）：`app_id` 与 `app_secret` 由联调负责人通过仓库外渠道提供，本文档不保存凭据值。
**参考实现**：`ApiAuthHelper.cs`

## 2. 数据模型定义

基于`Smt.Models.cs`文件，定义以下数据模型：

### 2.1 PickAndPutCommand（搬运命令）

完整模型定义：

```csharp
public class PickAndPutCommand
{
    [JsonPropertyName("device_code")]
    public string DeviceCode { get; set; }          // 设备ID: ARM01/ARM02

    [JsonPropertyName("command_code")]
    public string CommandCode { get; set; }         // 命令ID，需全局唯一

    [JsonPropertyName("timestamp")]
    public string Timestamp { get; set; }         // 时间戳，毫秒级

    [JsonPropertyName("task_type")]
    public string TaskType { get; set; }          // 命令类型: PICK_AND_PUT/SCAN/MOVE_FORWARD/MOVE_BACKWARD/MOVE_LEFT/MOVE_RIGHT

    [JsonPropertyName("priority")]
    public string Priority { get; set; }         // 优先级 (1-10, 10最高)

    [JsonPropertyName("timeout")]
    public string Timeout { get; set; }           // 期望完成时间(ms)

    [JsonPropertyName("source")]
    public LocationInfo Source { get; set; }       // 源库位信息

    [JsonPropertyName("target")]
    public LocationInfo Target { get; set; }      // 目标库位信息
}
```

### 2.2 LocationInfo（位置信息）

```csharp
public class LocationInfo
{
    [JsonPropertyName("location_id")]
    public string LocationId { get; set; }        // 位置ID: STATION_A/STATION_B/STATION_SCAN/STATION_WORK1

    [JsonPropertyName("location_type")]
    public string LocationType { get; set; }      // 位置类型: ONE_LAYER_RACK/FIVE_LAYER_RACK/SCAN_PLATFORM/BIN

    // ==================== 料箱信息 ====================
    [JsonPropertyName("bin_id")]
    public string BinId { get; set; }             // 箱子ID，ECS追溯用，可选

    [JsonPropertyName("bin_type")]
    public string BinType { get; set; }           // 箱子类型: 三格箱/六格箱

    [JsonPropertyName("bin_location")]
    public string BinLocation { get; set; }       // 箱子位置: A/B/C/D，单层货架上的储位

    [JsonPropertyName("bin_cell_location")]
    public string BinCellLocation { get; set; }  // 箱子单元格位置: 1-7

    // ==================== 料盘信息 ====================
    [JsonPropertyName("reel_layer")]
    public string ReelLayer { get; set; }         // 料盘层数

    [JsonPropertyName("reel_thickness")]
    public string ReelThickness { get; set; }     // 料盘厚度(mm)

    [JsonPropertyName("reel_totalthickness")]
    public string ReelTotalThickness { get; set; } // 料盘总厚度(mm)

    [JsonPropertyName("reel_diameter")]
    public string ReelDiameter { get; set; }      // 料盘直径: 7寸/13寸/15寸

    // ==================== 料架信息 ====================
    [JsonPropertyName("rack_id")]
    public string RackId { get; set; }            // 料架ID，ECS追溯用，可选

    [JsonPropertyName("rack_side")]
    public string RackSide { get; set; }          // 料架面数: A/B

    [JsonPropertyName("rack_layer")]
    public string RackLayer { get; set; }         // 料架层数: 1-5

    [JsonPropertyName("rack_column")]
    public string RackColumn { get; set; }        // 料架列数
}
```

### 2.3 ApiResult（API响应）

```csharp
public class ApiResult
{
    [JsonPropertyName("code")]
    public int Code { get; set; }                  // 状态码: 200成功, 400参数错误

    [JsonPropertyName("message")]
    public string Message { get; set; }            // 消息: "ACK" 或错误描述

    [JsonPropertyName("data")]
    public object? Data { get; set; }              // 可选，业务数据；为null时不输出该字段

    [JsonPropertyName("error_detail")]
    public ApiErrorDetail? ErrorDetail { get; set; } // 可选，错误详情；为null时不输出该字段
}
```

## 3. 命令接口

### 3.1 发送搬运命令

**接口描述**: 向指定的机械臂发送搬运命令，控制机械臂从源位置取料并放到目标位置。

#### 3.1.1 请求说明

**HTTP方法**: `POST`

**请求端点**: `http://<DEVICE_IP>:<PORT>/api/v1/device/command`

**请求头**:

```
Content-Type: application/json
```

#### 3.1.2 请求参数

| 参数名       | 类型   | 必填 | 说明                                                    | 示例值              |
| ------------ | ------ | ---- | ------------------------------------------------------- | ------------------- |
| device_code  | string | 是   | 设备ID，指定执行命令的机械臂                            | "ARM01" 或 "ARM02"  |
| command_code | string | 是   | 命令ID，需全局唯一                                      | "CMD-20251215-1001" |
| timestamp    | string | 是   | 时间戳，毫秒级                                          | "1702627300000"     |
| task_type    | string | 是   | 任务类型                                                | "PICK_AND_PUT"      |
| priority     | number | 是   | 优先级(1-10)，10最高                                    | 1                   |
| timeout      | number | 是   | 期望完成时间(ms)                                        | 30000               |
| source       | object | 是   | 源库位信息，见[LocationInfo](#22-locationinfo位置信息)   | -                   |
| target       | object | 是   | 目标库位信息，见[LocationInfo](#22-locationinfo位置信息) | -                   |

#### 3.1.3 task_type 枚举值

| 值            | 说明     |
| ------------- | -------- |
| PICK_AND_PUT  | 搬运操作 |
| SCAN          | 扫码操作 |
| MOVE_FORWARD  | 前进     |
| MOVE_BACKWARD | 后退     |
| MOVE_LEFT     | 左移     |
| MOVE_RIGHT    | 右移     |

#### 3.1.4 location_type 枚举值

| 值              | 说明                 | 可用位置ID                     |
| --------------- | -------------------- | ------------------------------ |
| ONE_LAYER_RACK  | 单层货架             | STATION_A, STATION_B(转运区域) |
| FIVE_LAYER_RACK | 五层货架             | STATION_A, STATION_B           |
| SCAN_PLATFORM   | 扫码平台             | STATION_SCAN                   |
| SCAN_NG         | NG平台               | STATION_NG                     |
| BIN             | 流水线料箱取放料工位 | STATION_WORK1/STATTION_SCAN1   |

#### 3.1.5 请求示例

**场景1: 入库步骤1 - 从单层货架取料放到扫码平台**

```json

    "task_type": "PICK_AND_PUT",
    "priority": 1,
    "timeout": 30000,
    "source": {
        "location_id": "STATION_A",
        "location_type": "ONE_LAYER_RACK",
        "rack_id": "RACK_001",
        "bin_id": "BIN_104",
        "bin_type": "三格箱",
        "bin_location": "A",
        "bin_cell_location": "1",
        "reel_layer": "10",
        "reel_thickness": "20",
        "reel_diameter": "15",
        "reel_totalthickness": "200"
    },
    "target": {
        "location_id": "STATION_SCAN",
        "location_type": "SCAN_PLATFORM"
    }

```

**字段说明**:

- `device_code`: "ARM02" - 使用2号机械臂执行

  - `location_id`: "STATION_A" - A侧单层货架

  - `bin_location`: "A" - 料箱在货架上的A位置
  - `bin_cell_location`: "1" - 料箱的第1个单元格
  - `reel_layer`: "10" - 料盘第10层
  - `reel_thickness`: "20" - 料盘厚度20mm
  - `reel_diameter`: "15" - 15寸料盘
  - `reel_totalthickness`: "200" - 料盘总厚度200mm
- `target`: 扫码平台，仅需location_id和location_type

#### 3.1.6 响应说明

**响应结构**: ApiResult

接收指令后统一返回 ACK 确认（正常接收、重复指令、参数异常均返回 ACK）：

| 字段名  | 类型   | 说明              |
| ------- | ------ | ----------------- |
| code    | number | 状态码: 200       |
| message | string | 固定: "ACK"       |

**响应示例**:

```json
{
    "code": 200,
    "message": "ACK"
}
```

**说明**:
- WMS 下发指令后设备统一返回 ACK 确认
- 重复指令（幂等处理）同样返回 ACK
- 指令参数异常时也返回 ACK，异常原因通过设备侧日志排查


## 4. 查询接口

### 4.1 查询设备状态

**接口描述**: 查询所有机械臂的当前状态。

#### 4.1.1 请求说明

**HTTP方法**: `GET`

**请求端点**: `http://<DEVICE_IP>:<PORT>/api/v1/device/status`

#### 4.1.2 请求参数

| 参数名      | 类型   | 必填 | 说明                              |
| ----------- | ------ | ---- | --------------------------------- |
| device_code | string | 否   | 设备ID(ARM01/ARM02)，不传返回全部 |

#### 4.1.3 响应说明

**响应结构**: devices 数组（与SMT流水线设备状态接口结构一致）

| 字段名  | 类型  | 说明                                        |
| ------- | ----- | ------------------------------------------- |
| devices | array | 设备状态数组，每个元素包含 device 和 state |

**device 对象（设备静态信息）**:

| 字段名             | 类型   | 说明             | 示例值                          |
| ------------------ | ------ | ---------------- | ------------------------------- |
| device_code        | string | 设备ID           | "ARM01"                         |
| device_name        | string | 设备名称         | "分拣机械臂1"                   |
| device_type        | string | 设备类型         | "ROBOTIC_ARM"                   |
| role               | string | 设备角色         | "SORTER_ARM"                    |
| supported_commands | array  | 支持的指令列表   | ["PICK_AND_PUT"]                |
| supported_events   | array  | 支持的事件列表   | ["SCAN_COMPLETED","ESTOP_PRESSED"] |

**state 对象（设备动态状态）**:

| 字段名               | 类型         | 说明                           | 示例值        |
| -------------------- | ------------ | ------------------------------ | ------------- |
| device_code          | string       | 设备ID                         | "ARM01"       |
| mode                 | string       | 运行模式                       | "AUTO"        |
| status               | string       | 设备状态（枚举值见下表）       | "RUNNING"     |
| is_online            | bool         | 是否在线                       | true          |
| current_command_code | string\|null | 当前执行的命令ID，空闲时为null | null          |
| scenario             | string       | 场景状态: success/error        | "success"     |
| updated_at           | number       | 状态更新时间戳(毫秒级)         | 1702627300000 |

**设备状态枚举值**（状态值 0~6，与PLC状态寄存器对应）:

| 数值 | 值      | 说明   |
| ---- | ------- | ------ |
| 0    | UNKNOWN | 未知   |
| 1    | IDLE    | 空闲   |
| 2    | RUNNING | 运行中 |
| 3    | ERROR   | 错误   |
| 4    | OFFLINE | 离线   |
| 5    | PAUSED  | 暂停   |
| 6    | STOPPED | 已停止 |

#### 4.1.4 响应示例

```json
{
  "devices": [
    {
      "device": {
        "device_code": "ARM01",
        "device_name": "分拣机械臂1",
```

## 5. 回调接口

回调接口由设备主动向WES（仓储执行系统）发起，用于回传任务执行结果或推送事件。

### 5.1 任务结果回传（Report Result）

**接口描述**: 设备完成搬运命令后，向WES回传任务执行结果。

#### 5.1.1 请求说明

**HTTP方法**: `POST`

**请求端点**: `http://<WES_IP>:<PORT>/api/v1/callback/result]`

#### 5.1.2 请求参数

| 参数名       | 类型   | 必填 | 说明                          | 示例值              |
| ------------ | ------ | ---- | ----------------------------- | ------------------- |
| command_code | string | 是   | 必须回传原指令ID              | "CMD-20251215-1001" |
| device_code  | string | 是   | 设备ID                        | "ARM_01"            |
| result       | string | 是   | 执行结果: SUCCESS 或 FAILED   | "SUCCESS"           |
| finish_time  | number | 是   | 完成时间戳(毫秒级)            | 1702627250000       |
| data         | object | 否   | 业务回传数据                  | -                   |
| error_detail | object | 否   | 错误详情(result=FAILED时必填) | -                   |

**data对象字段**:

| 字段名              | 类型   | 说明             | 示例值         |
| ------------------- | ------ | ---------------- | -------------- |
| actual_qty          | number | 实际操作数量     | 1              |
| pick_and_put_result | string | 放料指令具体结果 | "PUT_FINISHED" |

**pick_and_put_result枚举值**:

| 值           | 说明     |
| ------------ | -------- |
| PUT_FINISHED | 放料完成 |
| PUT_FAILED   | 放料失败 |
| PICK_FAILED  | 取料失败 |

**error_detail对象字段**:

| 字段名        | 类型   | 说明              | 示例值 |
| ------------- | ------ | ----------------- | ------ |
| error_code    | string | 错误码，0为无错误 | "0"    |
| error_message | string | 具体错误信息      | ""     |

#### 5.1.3 请求示例

**成功回传示例**:

```json
{
  "command_code": "CMD-20251215-1001",
  "device_code": "ARM_01",
  "result": "SUCCESS",
  "finish_time": 1702627250000,
  "data": {
    "actual_qty": 1,
    "pick_and_put_result": "PUT_FINISHED"
  }
}
```

**失败回传示例**:

```json
{
  "command_code": "CMD-20251215-1001",
  "device_code": "ARM_01",
  "result": "FAILED",
  "finish_time": 1702627250000,
  "data": {
    "actual_qty": 0,
    "pick_and_put_result": "PUT_FAILED"
  },
  "error_detail": {
    "error_code": "1001",
    "error_message": "Target position blocked"
  }
}
```

**字段说明**:

- `command_code`: 必须与原发送的命令ID一致，用于任务追踪
- `result`: "SUCCESS"表示命令执行成功，"FAILED"表示执行失败
- `finish_time`: 任务完成的精确时间戳
- `data.actual_qty`: 实际完成的搬运数量
- `data.pick_and_put_result`: 具体执行结果，成功时为"PUT_FINISHED"
- `error_detail`: 仅在result="FAILED"时需要提供，说明失败原因

#### 5.1.4 响应说明

WES接收到回调后，需要返回确认响应。

**成功响应示例**:

```json
{
    "status": "SUCCESS",
    "message": "ACK",
    "code": "200",
    "trace_id": "DEV-LOG-1702627300000"
}
```

**失败响应示例**:

```json
{
    "status": "FAILED",
    "message": "Invalid parameters",
    "code": "400",
    "trace_id": "DEV-LOG-1702627300000"
}
```

## 6. 错误处理

### 6.1 HTTP状态码

| 状态码 | 说明         | 处理建议                         |
| ------ | ------------ | -------------------------------- |
| 200    | 成功         | 正常处理响应数据                 |
| 400    | 请求参数错误 | 检查请求参数格式和必填字段       |
| 503    | 设备忙/故障  | 等待设备空闲后重试或联系技术支持 |

### 6.2 业务错误码

| code | 说明     | 处理建议     |
| ---- | -------- | ------------ |
| 200  | 成功     | -            |
| 400  | 参数错误 | 检查参数格式 |
| 503  | 设备忙   | 等待后重试   |

### 6.3 设备错误码（error_code）

| error_code | 说明           | 处理建议               |
| ---------- | -------------- | ---------------------- |
| NONE       | 无错误         | -                      |
| 1001       | 目标位置被阻挡 | 清理障碍物后重试       |
| 1002       | 取料失败       | 检查物料位置是否正确   |
| 1003       | 放料失败       | 检查目标位置是否可访问 |

### 6.4 错误处理示例

```csharp
public async Task<bool> SendCommandWithErrorHandling(PickAndPutCommand command, int maxRetries = 3)
{
    int retryCount = 0;

    while (retryCount < maxRetries)
    {
        try
        {
            var result = await SendCommandAsync(command);

            if (result.Status == "SUCCESS" && result.Code == "200")
            {
                return true;
            }

            // 设备忙碌，等待后重试
            if (result.Code == "503")
            {
                Console.WriteLine($"设备忙碌，等待后重试... (第{retryCount + 1}次)");
                await Task.Delay(5000);
                retryCount++;
                continue;
            }

            // 参数错误，不重试
            if (result.Code == "400")
            {
                Console.WriteLine($"参数错误: {result.Message}");
                return false;
            }

            // 其他错误，不重试
            Console.WriteLine($"命令发送失败: {result.Message} (错误码: {result.Code})");
            return false;
        }
        catch (Exception ex)
        {
            retryCount++;
            Console.WriteLine($"发送命令异常: {ex.Message} (第{retryCount}次)");

            if (retryCount >= maxRetries)
            {
                Console.WriteLine("已达到最大重试次数，放弃发送");
                return false;
            }

            await Task.Delay(5000);
        }
    }

    return false;
}
```

```csharp
            var content = new StringContent(json, Encoding.UTF8, "application/json");

            var response = await _httpClient.PostAsync("/api/v1/command", content);
            var responseContent = await response.Content.ReadAsStringAsync();

            return JsonSerializer.Deserialize<ApiResult>(responseContent);
```
