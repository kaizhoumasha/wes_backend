# 人工拣料四点扫码与退箱入队设计

## 目标与现状

本设计只闭合 `manual-picking` 的逐箱扫码、点位放行、WMS 人工作业准入与完成、退箱 FIFO 入队。`prepare`、`plan_delta`、货架 Transport 以及 WMS/设备的可靠收发沿用现有能力；不在插件里再造 HTTP、Celery、重试或物理互锁。工作线未启用插件时不触发新业务，已冻结的命令与结果仍由宿主可靠保存和对账。

当前人工出库合同 §3 的点1自主步进、点2不可读码处置、点3未知时停线、点4只记录扫码，与本次现场确认不一致。实施时直接修订该合同及过时的过程文档，不保留并行口径。`docs/hardware/` 厂商原始资料不清理。

## 身份与现场配置

- 6 合一编码属于物料，不作为料箱身份。料箱的业务身份是 `bin_code`，形如 `A00000xxxx`。本轮按 ECS `SCAN_COMPLETED.data.bin_code` 读取，实际扫码值带 `-A/-B/-C/-D` 后缀；插件保存原值和本次扫码 Evidence，按各点规则校验，传 WMS 时只传去后缀的正常箱码。没有 `barcode` 别名或兼容读取。
- 设备角色只使用 `definition.py` 的 `SCAN1`～`SCAN4`；现场 `KT16` 当前绑定依次为 `STATION_SCAN9`～`STATION_SCAN12`。业务代码不写死设备编号，使用工作线冻结的角色绑定。点位规则分别定义：SCAN1 `-B`、SCAN2 `-C`、SCAN3 `-B`、SCAN4 `-B`；相同值也不合并成全局校验策略。
- 料箱的 NG、正常准入与当前通过记录只属于本次经过，不写成条码的永久属性。每次经过以 SCAN1 Evidence 建立唯一身份；SCAN2 按点1→点2队首及实际扫码关联，SCAN3/4 仅用本次实际箱码匹配唯一未闭合经过及前序决定，歧义时不得授予正常放行。不可读码没有可伪造的正常 `bin_code`，但必须保留原事件、点位与命令因果身份。

## 逐点决定

| 点位 | 当前证据与判断 | 业务决定 |
| --- | --- | --- |
| SCAN1 入口 | 当前扫码符合本点 `-B` | 创建一次 `MOVE_FORWARD`，物理结果闭合后进入点1→点2单通道缓存；按实际可靠到达顺序冻结其 FIFO 身份。 |
| SCAN1 入口 | 不可读、箱码无效或后缀不是 `-B` | 记录本次 NG，创建一次 `MOVE_RIGHT`，走 SCAN1→SCAN3；不向 WMS 报一个猜测的箱码。 |
| SCAN2 工作位 | 当前扫码符合本点 `-C`，且与本次已进入缓存的料箱身份一致 | 用正常 `bin_code` 和当前 `task_id` 创建唯一 `outbound.manual_bin.work_admission_decide@v1` 义务。`WORK_REQUIRED` 保持等待 WMS `work_completed`；`NO_WORK` 正常 `MOVE_FORWARD`；`WAIT` 或结果未知不放行。完成事件必须匹配冻结的任务和本次等待，NG/正常结果均以 `MOVE_FORWARD` 释放到 SCAN3，并保留处置结果供 SCAN3 判断。 |
| SCAN2 工作位 | 不可读、箱码无效、后缀不是 `-C`，或与当前缓存身份不符 | 保存本次异常及 NG 决定，不请求 WMS；创建一次 `MOVE_FORWARD` 到 SCAN3。不能用当前扫码覆盖已冻结的其他料箱身份。 |
| SCAN3 退箱检验 | 当前扫码符合本点 `-B`，且能唯一关联本次经过的确定正常处置 | `MOVE_FORWARD` 到 SCAN4。此点不按点1→点2 FIFO 队首推断身份：它同时接收 SCAN1→SCAN3 和 SCAN2→SCAN3，两个来源可能交错。 |
| SCAN3 退箱检验 | 已有本次 NG，或不可读、后缀无效、找不到唯一的正常授权 | `MOVE_LEFT` 到 NG 出口；保留无法关联等异常证据，不伪造 WMS NG。此点按现场约定不停箱。 |
| SCAN4 退箱入队 | 当前扫码符合本点 `-B`，且能唯一关联 SCAN3 已放行的正常经过 | 创建一次 `MOVE_FORWARD`。该命令匹配的 ECS `SUCCESS` 结果是进入 `RETURN_BUFFER` 的权威闭合证据；收到前不入队，收到后按 SCAN4 到达事件的冻结顺序写入本线退箱 FIFO。 |
| SCAN4 退箱入队 | 不可读、后缀无效、身份或前序正常授权不确定 | 保持点位占用，不下发 `MOVE_FORWARD`，不写退箱队列；保留证据等待现场对账。 |

SCAN1→SCAN2 是单通道 FIFO，不允许越过未闭合队头。SCAN3 不使用该 FIFO 作分流依据。`RETURN_BUFFER` 是本工作线严格 FIFO：只有已物理入队的正常料箱可进入 `outbound.bin.return_batch@v1` 候选，未闭合队头不能被后续候选越过。
各扫码设备的新方向命令不得越过该设备未闭合的旧命令，不能因料箱下游经过已关闭而解除旧设备命令围栏。SCAN2 异常也须先证明队首点1命令成功；随后虽向前放行，但不冒认队首，保留异常证据并冻结原队首，直到现场对账。SCAN3/4 对同一未闭合经过的重扫不改变首次方向、命令或 FIFO 时间；已知和未知料箱都遵守本点设备命令围栏，后续事件只留证对账。NG 出口命令成功后，本插件结束该经过的本线责任，不等待 NGZone 人工处理。

## 宿主与插件边界

宿主继续负责 ECS 回调有界接收、Evidence 去重与领取、工作线及设备角色绑定、可靠 DeviceCommand、WMS Confirmation、结果/超时/未知状态与原身份对账。增加的基础接缝仅把冻结工作线的设备事件、命令结果和 typed WMS 结果可靠交给其已装配插件；该接缝不得导入 `manual-picking`，不得按当前安装状态丢弃已冻结义务，也不为每个插件动态注册 Celery task。

插件内由 `plugin.py` 显式装配四个点位 handler 和必要的当前经过/退箱状态应用。handler 只计算该点位的业务决定，不直接执行 HTTP、Celery、数据库或 ECS I/O；应用层在同一事务内冻结因果身份、当前经过状态及宿主可执行的唯一意图。现有 `FactReference` 强制 `MaterialExecution` 身份，不能为不可读料箱虚构物料执行来凑接口；宿主补一条最窄的通用工作线插件消费端口，复用既有 Evidence 领取和可靠结果通道，不建立第二套事件总线。点位 handler 可复用现有 `@handler` 元数据规则，但不放宽已有物料执行 Fact 合同。

同一事件重放只复用原决定与命令；结果未知、超时或 ECS 已接纳但未给权威终态时，保留原命令、证据、点位占用及顺序围栏，不换身份重发、不释放或入队。WMS `ACCEPTED`、设备 ACK 与本地命令创建均不是物理完成。

## 实施与验收边界

先闭合四点输入/决定与点位独立后缀测试，再闭合宿主可靠投递、WMS 完成应用及 SCAN4 物理成功后入队；最后修订人工出库合同与当前导航，移走过时过程文档。插件业务测试只放在 `workline_plugins/manual-picking/tests/`；基础接缝与设备/WMS wire 测试留在各自所有者目录，不用一层测试替另一层背书。

验收至少覆盖正常 `-B/-C/-B/-B`、SCAN1 NG 直达 SCAN3、SCAN2 本地 NG、WMS `WORK_REQUIRED/NO_WORK/WAIT`、SCAN3 双来源交错、SCAN3 未知不停箱走左、SCAN4 不可读停箱、SCAN4 ACK 但未成功不得入队、重复/迟到结果以及严格退箱 FIFO。自动化测试证明代码合同；只有现场 ECS 的匹配权威结果才能证明真实物理入队。
