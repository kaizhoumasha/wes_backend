## 1. 目标与真源边界

ECS/RCS 负责接纳、物理资源互斥、排队、执行和现场恢复；WMS 负责业务有效性、库存、储位分配与最终对账。WES 可靠保存请求和结果、执行业务决策接入、自动恢复消息处理，不要求操作员解锁、清除异常、重建任务或点击重处理才能继续正常生产。

验收目标是：旧任务没有结果，工人清障后新任务仍能提交并被 ECS/RCS 正常执行；旧结果晚到只补原任务；WMS 恢复后待传递事实自动续送。仅证明新请求可以入队，不算通过。

本设计替代 2026-09-10 本站恢复设计和实施计划中的长期物理围栏及收窄交付范围。两份旧文件移至项目外归档，已实现代码仍是当前行为，不能把本设计当作已部署事实。其他有效合同继续描述现状；本设计中列出的差异须在实施时同步修改，不默认为供应商已经支持。

日常仓库工作人员无需登录 WES，也不承担 WES 告警确认、任务解锁或数据修复。前端面向 IT、设备工程师和运维人员，提供配置、调试和诊断；专业操作不是日常任务续行的前置条件。静默表示不要求人工介入，不表示丢弃异常或失去可观测性。

## 2. 职责与依赖

| 所有者 | 负责 | 不负责 |
| --- | --- | --- |
| WES 基础 | DeviceCommand、TransportTask、Evidence、幂等、事务领取、可靠投递、只读诊断 | 库存分配、现场物理占用推测、具体工作线流程 |
| WES 业务插件/协调器 | 本站事件结合 WMS 决策形成指令；按任务身份消费结果；判断业务请求是否仍有效 | 重复实现可靠投递；替 ECS/RCS 调度设备；人工数据对账 |
| ECS/RCS | 原子接纳、设备/机器人/货架等物理互斥、执行与恢复、权威结果 | 由 WES 历史异常决定是否允许运行 |
| WMS | 业务决策、库存/储位约束、业务纠正、最终对账 | 要求 WES 人工删记录后才能恢复消息 |

基础可独立部署、运行和测试，不导入具体插件；业务必须通过基础端口执行。Transport 现有链路通过 WMS Adapter 接入，保持实际路由，不假定 WES 直接连接 RCS。

## 3. 限制的删除与保留

| 当前机制 | 目标 |
| --- | --- |
| 同设备 ACKNOWLEDGED/RECONCILING 阻止后续领取 | 删除；独立命令可提交，由 ECS 接纳时裁决 |
| 同设备 DISPATCHING 唯一索引及全局领取锁 | 删除设备级串行限制；保留每条命令的 claim token 和数据库原子领取 |
| TransportResourceBinding 的 BIN/RACK 活动唯一占用 | 删除整个占用 owner；任务成员已提供资源关联，避免再造一张非互斥绑定表 |
| PositionProjection 的未知位置/旧所属工作线拒绝有效新请求 | 不作为新请求准入依据；投影是观察结果，不是物理资源授权 |
| 调试轮次占用货架阻止其他独立任务 | 删除跨任务资源占用；单轮步骤幂等与自身流程次序保留 |
| blocker、reconcile-device-idle、人工 reprocess 作为续行步骤 | 退役对应接口、实现、字段、权限和 UI 消费者，不保留兼容入口 |
| 同一请求身份不同正文、重复 worker、旧 worker 写回 | 保留单任务幂等、正文冲突校验、claim token；仅影响该消息 |
| 显式停用工作线、请求结构缺失或无业务授权 | 保留；不把历史未知当作这些条件 |

Status 用于诊断，不再以 WES 发送前的 IDLE/active-command 快照证明可以执行。ECS 在接纳当时判断；明确未接纳可按原身份延后。请求所需的来源/目标等参数仍必须完整，但不能因本地旧投影不一致拒绝 WMS 已给出的有效请求。缺少必要参数只结束或等待该请求的业务决策，不能阻断设备其他请求。

## 4. 请求、结果与恢复规则

### 4.1 请求

- 新业务意图使用新请求身份；网络重传沿用原身份和冻结正文。禁止 WES 因超时换身份重做旧物理动作。
- 保留现有事件规范化摘要，不新增事件总线或全局序列。ECS 必须保持重报的原 timestamp 和核心内容；新的独立事件必须具有不同的发生标识内容（现合同包含 timestamp）。若供应商不能区分同毫秒同内容的两个事件，接入验收不通过，不能由 WES 猜测。
- 明确未接纳：在请求仍有效时退避续送；请求过期只记录该请求未执行。
- CEO D7 已接受：明确接纳后，WES 停止该命令的提交重送；执行和恢复由接纳方负责。结果超时仅记录待结果/未知，不阻止独立任务；重复 ACK 不触发再次提交，既有合同提供结果查询时可以按其语义读取，但不把提交接口当查询接口。
- 交付未知：不阻止其他任务、不换身份重做。仅当既有接入合同保证原身份原正文重传不重复执行，且仍在允许重试的有效期内时，才允许重送；否则保留未知并接收后续事实，不新增人工恢复门禁。此规则不适用于已明确接纳的命令。
- 业务有效期与 WES 内部观察期限分开。观察期限到达不代表远端失败；已作废或已经失效的业务动作不可因网络恢复而执行。

### 4.2 结果关联

先可靠保存合法消息，再异步关联和应用。只有原任务身份、来源系统/设备、冻结对象及结果版本相符时才应用。资源编号相同不足以匹配任务。

| 情况 | WES 行为 |
| --- | --- |
| 原任务存在且原来结果未知 | 自动补事实，记录真实结果并可靠发布 |
| 原任务不存在 | 保存未关联记录并退出活跃重试，不伪造任务；对应任务建立时按精确身份可靠触发匹配，不扫描全部历史异常 |
| 原任务存在但业务上下文已失效/工作线已停用 | 保存并补充原任务事实；不恢复旧业务动作，不要求重建上下文；合法历史结果仍交付原有接收方 |
| 同身份同版本同内容 | 返回稳定接收结果，不重复驱动或重复推进 |
| 同身份同版本不同内容 | 保留冲突诊断，不覆盖；影响限于该消息，由来源系统纠正 |
| 低版本迟到 | 保留历史，不回退已应用的高版本 |
| 新任务成功、旧任务无结果 | 当前点位显示近期交互正常；旧任务仍显示未知 |

CEO D8 已接受：未关联记录不参与周期性全量或反复扫描。任务建立时复用已有持久化工作登记与提交后唤醒，登记按精确任务身份匹配的工作；Beat 只补未完成的匹配工作。任务与结果并发建立时，两条路径必须保证至少一方看见另一方或留下可靠匹配工作，不能只依赖一次易丢失通知。没有对应任务变化时，记录安静留存，专业人员可查询，仓库人员无需操作。

未知任务的合法回调在持久化后返回接收确认，不再要求 ECS 先修复 WES 的本地任务。非法结构/无法识别的来源仍按合同拒绝，不能把所有输入都解释为合法结果。持久化失败不返回成功。

### 4.3 复用来源系统的恢复结果

ECS/RCS/WMS 的既有恢复机制是本方案输入，WES 不建立第二套异常处置状态机，不发明恢复指令，不要求供应商为 WES 新增必填 result_revision。上一版预设该字段的建议撤回。

核对实际回调如何表达原任务继续、恢复结果以及业务作废；WES 按既有任务身份与合同接收。Transport 复用 outcome_revision、位置事实版本和内部 outcome_version。ECS 若已有权威顺序或状态语义则直接映射，不能由 WES 的接收时间制造远端顺序。

同一命令恢复后的不同结果不能一律作为重复丢弃。消息去重与任务当前结果更新分别判断：事实保留，能按来源合同判断的自动应用；不能判断先后的事实只留存待诊断，不猜测覆盖、不阻塞新任务、不要求仓库人员处理。

工程评审 ENG-D1 已确认：当前 `device_evidence_service.py` 将结果身份固定为 `RESULT:{command_code}`，不同结果会触发 Evidence 载荷冲突；结果应用分支及 `DeviceCommand` 状态机同时排除了 FAILED 后恢复。T1 必须同时处理这两层限制，不能仅删除设备围栏。复用现有 Evidence 与报文规范化摘要能力，将消息去重身份与原命令关联身份分开；同一命令的不同结果分别留存，只有既有 ECS 合同可判定的恢复事实才能更新原命令。摘要只判断消息重复，不证明结果顺序；不得按到达时间覆盖、不新建任务、不重发动作。供应商实际恢复语义仍在 T0 核验，不以本次方案确认代替实测。

### 4.4 资源投影与迟到结果

资源投影只服务诊断及业务读取，不决定独立请求能否下发。每任务的结果和位置是可追溯事实；跨任务不能比较各自 revision，也不能按 HTTP 到达时间推断物理先后。

CEO 评审 D6 已接受：删除新任务创建时替换“当前观察任务”并将位置标为未知的设计，不新增观察占位字段。任务创建、发送超时或拒绝都不是位置变化事实，不能据此改写已保存位置。

位置记录保留来源任务、来源消息及事实时间，页面只称“最近已知位置”，不承诺实时物理位置。来源合同能证明跨任务先后时才更新聚合位置；不能证明时分别保留任务结果与位置事实，不按任务创建顺序、HTTP 到达顺序或不同任务的 revision 比较结果。聚合信息明确标注当前未确认，不能被业务消费者当作新的执行授权。

实际位置及物理冲突由 ECS/RCS 裁决。业务指令所需位置来自有效业务决策或既有权威事实接口；WES 不用观察占位或历史推测补齐。短事务只保护同一条事实及聚合记录的并发写入，不跨网络 I/O，不作为任务接纳门禁。

## 5. WMS 恢复与业务层完成条件

复用 WmsConfirmation 的 RETRY/NOT_SENT/DELIVERY_UNKNOWN 自动续送，不新增恢复 worker。取消历史上下文状态对“已保存事实向原接收方交付”的阻止；对“重新发起物理动作”的业务有效性校验仍由业务所有者执行。

已保存的确定响应不能被自动重试改写。WMS 已纠正业务决策时，通过对应 operation 的既有作废/新请求或版本化更正合同表达；WES 自动消费，不要求人工改库。没有这种机器合同的 operation 不得声称实现了业务纠正。本次必须为现场使用的 return_batch、prepare 逐项记录可用的原合同路径和实测证据；缺口属于该业务切片未完成，不能再次移出范围却宣布整体恢复完成。

具体插件的新本站请求不得依赖旧任务终态才能进入决策；真正同一任务的业务依赖仍由 WMS/插件决定。自动联调轮次也不能在失败步骤无限等待：记录该步异常后重新取得有效业务决策再进入下一步，禁止沿用已经失效的旧目标。核心测试不替代这些业务验收。

工程评审 ENG-D2 已确认：`PickingTaskPrepareCoordinator._runtime_context_ready` 当前用整线 `get_unfinished_workload_summary` 的 `any(by_type.values())` 阻止 prepare，其中包含历史 DeviceCommand、TransportTask 和 Evidence。T4 必须将历史记录统计与业务准入分开：历史异常及待反馈记录继续保存和处理，不作为新 prepare 的统一阻断条件；新请求由有效 WMS 决策和对应业务规则判断。不能直接删除已有有效 PickingTask 的业务约束，也不能伪造旧任务完成来放行。共享统计仍有配置等消费者，不通过清空统计或全局排除异常记录达到准入目的。

工程评审 ENG-D3 已确认：`WorkLineStartService.start` 当前也以整线未闭合负载拒绝重新启用。将此入口纳入改造：历史异常和待反馈记录不阻止明确发起的重新启用；保留配置合法性和有效业务约束，不自动启用被明确停用的工作线，不清空共享统计或伪造旧任务终态。此处指工作线启用 API，不是进程重启。独立核查 safety incident 和插件阻断条件，区分明确停用要求与历史记录，避免另留人工解锁门槛；这不等于未经核查删除所有安全或业务判断。

工程评审 ENG-D4 已确认：急停记录、物理急停、复位和恢复执行全部归 ECS。`ESTOP_PRESSED` 不属于 WES ECS callback 合同，WES 必须在 Evidence 持久化和任何队列唤醒前以统一入站校验错误拒绝，不得将其降级为普通事件、插件事件或联调事件。WES 保留原 DeviceCommand 身份、状态和资源围栏，只等待 ECS 通过既有 DeviceCommand 结果/对账合同报告权威终态。WES 显式管理停用仍保留，不因 ECS 恢复自动启用。退役 `WorkLineSafetyService` incident、排空任务、`clear-estop` checklist/API/权限及全部消费者，不保留别名、空壳或兼容路径。接入验收仍需证明 ECS 自身的急停、复位、恢复排序和执行许可有效，本决策不替代现场验收。

工程评审 ENG-D5 已确认并由 T4b/T5c 本地实施：WMS 合法修正计划通过现有 `PickingTaskPlanDeltaService.validate_plan`、`apply_plan` 在正常 record/replay 路径自动校验和应用；超级管理员 `apply-correction` route、DTO、service method、权限与 OpenAPI 合同已退出，不新建纠正服务。历史 `plan_blocked_evidence_id` 不先于业务校验拒绝新计划；已保存为 RECONCILING 的同 identity 同正文消息重报也重新校验。任务身份、正文、版本、owner、并发和业务有效性校验保留；有效纠正原子应用并解除精确匹配 blocker，历史错误 Evidence/拒绝保留。无法确认的消息不推进该计划，也不阻断独立新任务；不得修改相同 identity 正文或跳过计划版本。真实 PostgreSQL/WMS 验收仍待 T6。

工程评审 ENG-D6 已确认：退役自动联调 `TransportDebugRunService._prepare_return_batch` 在 WMS 返回 `NO_BATCH` 时以历史出库原槽位生成退箱动作的约定。`NO_BATCH` 表示本次没有可执行批次，不生成 Transport、不标为物理执行失败；当前步骤等待有效 WMS 决策，独立任务继续。按既有 return_batch 合同用新 operation_id 再次请求，取得有效 READY 后才形成动作；网络重试仍保持原请求身份与正文。历史出库位置只作为事实留存，不能代替当前 WMS 授权。再次请求须有持久化的等待节奏和当前请求有效性判断，不能每次 worker 唤醒都创建新请求，也不能借重试继续使用已失效候选。

## 6. 实施前的接入验收条件

下列为外部能力核验，当前不宣称通过。可以先完成本地设计与实现，但不允许在缺证据时部署并宣称无阻塞恢复完成。

1. ECS/RCS 能同时接收相同资源的独立任务，原子排队或明确拒绝，绝不由两个已接纳任务并发误操作同一对象。
2. 相同请求身份重传、进程重启、ACK 丢失不会重复驱动；幂等保存期限覆盖允许重试的期限。未证明的通道不得开启交付未知重送。
3. 按 ECS 既有机制识别原 command_code 的恢复结果；Transport 沿用既有 revision 合同。核验的是 WES 正确接入，不要求对端重建恢复机制。
4. 事件重传与新事件可区分；物料人工移走后后续事件独立触发，不要求“对象确认退出”指令。
5. WMS 能接收对应 operation 的事实并完成纠正/对账，重复与迟到结果不会重复扣账；没有回传合同的孤立消息只本地留存，不虚称 WMS 已收到。

| A6 | 旧任务成功晚于新任务结果 | 旧任务可补正，但不能覆盖新任务关联的位置投影或重启旧动作 |
| A7 | 结果先于任务/原上下文被清除 | 结果保存并 ACK；可关联时自动关联，否则留存且不影响后续任务 |
| A8 | WMS 503 后恢复/返回确定错误后业务纠正 | 前者原义务自动续送；后者按业务纠正合同自动消费，不手工重建 |
| A9 | 工人移走卡住物料，下一个点位正常 | 新事件正常处理；点位健康与旧任务异常分别展示 |
| A10 | WES 在落库后、发布前重启；Redis 通知丢失 | 现有数据库记录和 worker/Beat 自动恢复，无重复业务推进 |
| A11 | 重复/冲突/乱序回调 | 重复幂等、冲突隔离、版本不回退，不阻止不相关任务 |
| A12 | 仓库工作人员不登录 WES、专业人员关闭前端后故障恢复 | 调度和记录继续自动运行；配置/诊断页面不是续行条件 |

## 8. 简化、文档与交付

不新增通用恢复平台、资源调度器、Saga、全局事件序列、兼容开关或旧数据迁移逻辑。复用已有 owner；不预设新增对外恢复字段；内部字段仅在无法复用且有明确用途时增加。以随机 Alembic revision 更新最终 schema，开发/测试库可清理，但不擅自清理现场库。

删除退出的占用模型、方法、DTO、权限、UI 和无消费者测试；测试按原所有者修改，不保留旧实现换名副本。纯文档变更不编写测试。docs/hardware 原始资料全部保留。

代码验证、基础真实进程验证、业务插件验证、供应商接纳验证、部署及现场验收分别报告。整体完成要求 A1–A12 闭合；基础切片通过不能代替业务切片或现场验收。

### CEO 扩展 D3：任务关联诊断（已接受）

用户选择纳入。专业人员从现有任务详情查看现场请求、WMS 决策、WES 下发、对端接纳、执行结果及原任务恢复事实。复用现有身份、Evidence 和可靠义务查询，不新建日志平台或恢复引擎。不存在或不能精确关联的环节显示“未观察到”，不能根据资源相同或时间接近拼接因果，也不能把 ACK 显示为物理完成。界面关闭不影响处理。

查询分页、有界返回；无结果、部分记录、加载失败分别展示。基础诊断只返回通用关联事实，业务决策解释由对应业务消费者提供，核心不得导入具体插件。

### CEO 扩展 D4：等待与积压诊断（已接受）

在现有专业诊断页面展示等待环节、已等待时长、最近尝试及下一次重试时间，复用任务、Evidence 和可靠投递记录。区分待发送/退避、已接纳待结果、WES 本地待处理或待发布；多个环节同时等待时分别展示，不把本地积压归责于设备。未安排重试时显示“未安排”，无相关时间时显示“无记录”，不编造倒计时。

展示基于持久化时间并注明数据更新时间，页面断连或查询失败不显示正常；历史未知结果不计作 WES 待发送积压。只读查询有界分页，不新增独立监控平台、自动设备故障判定或恢复按钮。

### CEO 扩展 D5：单任务排查记录导出（已接受）

IT、设备工程师和运维人员可从现有任务详情导出该任务的排查记录。复用 D3 的精确关联查询与事实模型，包含任务身份、相关请求/响应、时间、处理结果、缺失环节及导出时刻。只覆盖 WES 实际保存的事实，不表示对端内部完整日志或物理完成证明。

导出采用固定字段的 JSON 文件，浏览器下载，不自动发送、不另建服务、存储库或 PDF 模板系统。复用现有诊断读取权限，排除认证头、凭据及与该任务无关的数据。对超出导出上限的记录明确说明截断及范围，不能把部分记录标为完整。导出失败只影响下载，不影响调度与记录。

### CEO D9：错误分类与处理边界（已接受）

| 故障 | 处理 | 专业人员可见信息 |
| --- | --- | --- |
| 网络中断、合同明确暂不可用 | 在请求仍有效且合同允许的前提下退避重试 | 对端、任务身份、原因、最近尝试与计划时间 |
| 已明确接纳但结果未到 | 只等待和记录，不重送已接纳命令 | 已接纳、待结果及等待时间 |
| 同身份内容冲突、必要字段错误 | 留存可保存的错误诊断，退出自动重试；按入站合同返回错误，不将非法消息伪装成成功 | 具体字段/冲突身份及来源 |
| WES 数据库不可用 | 事务失败不确认保存成功；恢复后由既有可靠投递/原发送方重试续接 | 本地依赖错误；不得误报对端故障 |

错误分类由已有领域 owner 承担，不新建通用恢复平台或第二套队列。单条数据错误只影响该条；依赖整体不可用时不得用捕获异常并继续来伪造已处理。日志保留任务身份、环节与具体原因，不记录凭据。退出重试不等于删除事实，来源系统后续合法纠正仍按既有合同接纳。

### CEO D10：受控切换（已接受）

采用计划维护窗口统一切换 WES，不滚动混跑新旧写入进程，不增加兼容模式。暂停新调度，确认正在进行的提交事务已完成或保留为交付未知后停止旧 API/worker/Beat；按最终 schema 更新数据库、后端和前端，再启动新进程，先验证持久化与接口，后恢复调度。不得清除任务、恢复已接纳命令的提交或中断 ECS/RCS 已接纳任务。未成功保存的窗口内回调由既有发送方可靠重传，发布前须演练证明。

新版本验证失败时保持 WES 新调度暂停，不用启动旧代码硬接新 schema。切回前验证旧代码与数据库结构匹配；如无法无损恢复匹配结构，则保持维护并修复新版本。不得靠删除任务/覆盖现场数据回滚；回滚也不重做已经在 ECS/RCS 执行的动作。维护时长、可用的 schema 逆向步骤以及回调重传覆盖窗口由发布演练给出，不预估为零停机或自动保证。

### 错误与失败路径登记

以下类名来自当前代码；“目标处理”是实施要求，未声称现状已实现。协议结果是可判定的返回值，不能伪造为不存在的异常类。

| 路径 | 当前类/协议结果 | 目标处理与可见结果 | 验证所有者 |
| --- | --- | --- | --- |
| Device 创建身份冲突 | DeviceCommandIdentityConflictError | 该请求拒绝，保留身份冲突原因，其他任务继续 | test_device_command_service.py |
| ECS 结果找不到命令 | UnknownDeviceCommandError | 合法回调落库 ACK，改为未关联留存；相关任务出现时可靠匹配 | test_evidence_service.py + 真实库事务测试 |
| ECS 不同内容/乱序 | DeviceResultConflictError、DeviceResultOutOfOrderError | 核对既有恢复语义；保留事实，不猜测覆盖，不把所有恢复结果拒绝为重复 | test_evidence_service.py、test_evidence_identity.py |
| Transport 身份/结果不符 | TransportIdempotencyConflict、TransportContractError | 单消息冲突隔离，保留任务/消息身份，不重建任务 | test_transport_service.py、test_transport_reconciling_facts.py |
| WMS 请求/响应冲突 | WmsConfirmationIdentityConflictError、WmsConfirmationResponseConflictError | 停止该错误重试；合法业务纠正走既有业务入口 | test_wms_confirmation_service.py、对应业务测试 |
| 明确未接纳/网络暂不可用 | RETRY、NOT_SENT、DELIVERY_UNKNOWN 等既有分类 | 按接入合同及请求有效性退避；已接纳不适用重送 | test_dispatch_service.py、test_wms_confirmation_dispatch.py |
| DB 连接/事务失败 | SQLAlchemy DBAPIError/OperationalError；唯一冲突为 IntegrityError | 回滚不确认成功；不把所有 IntegrityError 包装成资源占用 | 原仓储/真实库测试 |
| 旧位置准入拒绝 | PositionProjectionAuthorityError | 移除旧占用/未知投影门禁；明确停用与真实参数错误仍按独立规则处理 | test_transport_execution_authority.py |
| 页面查询/导出失败 | 现有 HTTP/前端请求错误返回 | 错误/陈旧可见，不把失败当空或正常，不改变任务 | 原 API 与组件测试 |

每条失败须可重试、明确拒绝或留存；没有“静默丢弃并继续成功”的路径。计划已定义处理，但 ECS 结果映射及 WMS 业务纠正的机器合同尚未完成当前代码核对，进入工程评审后优先闭合；不能用用户确认对端具备恢复能力替代具体字段和调用点。
