# 工作线通用角色绑定

本合同经用户确认，采用约定大于配置。工作树实施及聚焦验证已完成，未提交、未部署，不作为现场验收证据。

## 所有权与配置

- Device 与 WorkLine 管理物理设备、连接和归属，不保存插件业务角色。
- 后端插件声明角色及业务能力；基础宿主通过已安装插件清单返回 `device_roles`，每项只有 `role_key` 和 `display_name`。
- 前端只有一张通用角色绑定表。用户选择插件后，将角色逐个绑定到本线实体设备，不需要安装前端插件或编写专属表单。
- 保存合同为 `config.device_bindings`：角色键映射到准确的 `device_code`。无插件保存空配置；草稿可缺项，启动必须齐全。
- 不接受未知角色、重复设备绑定或不在本次选择集合中的设备。切换插件清空角色绑定，保留物理设备归属；保存失败保留输入。
- ECS 清单提供设备身份、命令、事件和状态。ECS 的硬件 `role` 不等于插件业务角色，不重复手填固件、网关版本等设备事实。

## 约定大于配置

位置参数和设备标识含义不同，不因为当前设备清单缺少独立点位字段而自动视为相同。
WES 下发约定的逻辑位置参数，ECS 负责将参数解释为实际物理点位；不要求用户补充现场点位编码。
插件使用固定命令参数与执行策略，不提供工作线点位配置、私有参数表单或通用动态 Schema。
角色的业务含义、命令选择、结果解释和 WMS 交互仍归插件；宿主不认识粗分业务字面量。
粗分插件沿用已有位置角色作为逻辑参数：`MEASUREMENT_POSITION`、`PIPELINE_INLET`、
`PIPELINE_OUTLET`、`NG_POSITION`。这些是插件命令合同，不是对厂商现场地址的推测。
参数保留既有工作线/Epoch 上下文；实际 ECS 必须实现对应解释，Mock 验证不代表供应商已实现。

## 复用边界

复用现有配置 API、设备发现、Endpoint 访问、START 计划及 Epoch 冻结。保存时先校验本次配置和本次设备集合，再更新归属。
保留清线、停用、未完成动作与资源围栏检查。迟到事件不匹配当前业务时记录错误，不增加跨插件重投或兼容路径。

后端 `src/` 与 SDK 是基础能力，`workline_plugins/` 是业务实现，`deployment/plugin_composition.py` 显式关联可选安装的插件。
基础默认无插件，可独立运行和测试。前端是单应用，不再有业务插件目录、现场入口、插件注入或专属构建模式。
prepare 业务迁出保持独立范围。
