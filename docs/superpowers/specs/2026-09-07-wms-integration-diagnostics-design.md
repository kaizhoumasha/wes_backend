# WMS 联调诊断设计

日期：2026-09-07

状态：设计与工程计划评审已通过；后端切片已实施，正在执行授权交付门禁，前端页面接入待继续。实施证据与未完成项见配套实施计划；尚未部署或完成现场验收。

## 1. 目标与范围

WMS、WES 工程人员可在前端查看一次真实接口交互的合同要求、实际参数、字段差异和异常原因，减少人工比对 JSON 和反复解释合同。

第一版包括 SSE 实时控制台、双向交互记录、请求与响应字段对比、异常解释、诊断信息复制。数据来源仅为 WES 观察到的双方请求、响应及当次校验日志，不接入 WMS 内部运行日志，不扩建通用日志平台。仅观察真实调用；不增加报文编辑、重新发送、业务状态修改或场景执行功能。

覆盖当前正式静态接入的 WMS Operation：WMS → WES Event 入口和 WES → WMS Adapter 调用，包含 Transport 的已批准合同。未知 operation 显示不支持；未经过这些入口、未到达 WES 应用的请求不可推断为已捕获。实施清单必须逐项核对当前 operation inventory、Event 静态分派和出站 Adapter，不凭历史文档中的数量宣称全覆盖。

## 2. 已核实的基础

- `src/app/wms_adapter/v1/events.py` 已有有界读取、严格解析和部分入站异常摘要发布。
- `src/app/execution/models/wms_confirmation.py` 保存冻结请求及响应证据关联；不是每次发送尝试的日志。
- `src/app/execution/models/inbound_evidence.py` 保存规范化事实及业务应用状态；不能还原所有非法报文或重复调用。
- `src/app/wms_adapter/client.py` 的访问结果保留传输状态和 JSON 解码事实，未提供非法响应的原始正文。
- `src/app/sys/services/event_stream_service.py` 使用 Redis Pub/Sub，属于 live-only 通知，不能作为历史记录存储。
- `src/app/sys/models/audit_log.py` 面向用户操作审计，不具备双向 HTTP 请求响应及合同差异语义。
- 前端 `src/router/routes/ops.ts` 已有运维工具入口，可沿用现有列表、详情与权限机制。

## 3. 页面与使用流程

入口：运维工具 → WMS 联调诊断，建议路由 `/ops/wms-diagnostics`，具体父级路径按现有路由装配。

控制台按观察到达顺序显示时间、方向、operation、operation_id、已知业务关联、HTTP 状态、交互耗时、异常摘要。支持时间、方向、operation、operation_id、业务关联和异常筛选；只查询当前部署环境。每次交互先显示紧凑行，PAYLOAD 默认折叠；选中后在固定详情区显示合同差异，不因新日志到达丢失阅读位置。

点击记录打开详情，按以下顺序展示：

1. 异常结论：发生在请求、响应、业务应用还是传输阶段，以及明确的原因。
2. 请求／响应两个标签页：字段路径、合同要求或有依据的预期值、实际值、判定、规则来源；可切换“只看差异”。
3. 报文视图：采集到的请求和响应文本，标注脱敏、截断、未捕获、无响应或非法编码；不称作完整原始报文。
4. 已知关联：operation 身份、请求尝试标识、可靠义务／Evidence 标识；不同 identity 不按时间接近自动合并。
5. 复制诊断信息：版本、身份、异常、比较项、采集到的脱敏报文及完整性提示。

实时模式使用 SSE，直接替换定时轮询，不保留两套实时刷新路径。向上滚动或点击“暂停滚动”只停止跟随，仍在有界缓冲中接收并显示新增数量；“清空视图”只清本机显示。切换近期记录、隐藏或离开页面时断开实时连接，回到实时模式后重新连接并提示可能存在间隙；近期记录通过手动查询回看。

列表中的“接口符合合同”与“当次接口结果／采集时状态”分别显示，并注明 `observed_at`。后续业务处理不更新此历史快照；当前业务状态通过已存在且账号有权限访问的权威详情查看，不增加状态同步或业务轮询。合法业务拒绝、合法等待、DUPLICATE 都不能自动归类为合同错误；HTTP 200、接收 ACK 和物理完成不得混同。复制文案使用相同的快照措辞。


### 控制台呈现

WIRE 指应用层实际观察到的 Method、Path、必要 Header、HTTP 状态和正文；PAYLOAD 是正文中的业务内容。规范化 JSON、脱敏预览和网络原始字节不得混称，界面标注采集阶段与完整性。发送开始不证明 WMS 已接收，入站响应生成不证明对方已收到 ACK。

采用蓝灰工业诊断风格：背景 `#18232D`、面板 `#243340`、正文 `#E5EDF2`、方向强调 `#63B8CC`、提醒 `#E6B566`、错误 `#EF8278`。标题/控件复用项目中文字体，时间、身份与 JSON 使用本机等宽字体栈，不依赖外网字体。合同错误和传输异常用图标、文字和颜色共同突出，合法业务拒绝使用提醒标识；没有闪烁、打字动画或模拟命令输入。

宽屏为控制台与固定详情区并列，窄屏详情改为抽屉。保留键盘焦点、文本选择、复制、JSON 换行切换；新消息不抢焦点。

```text
WMS 联调控制台  ● 已连接  [搜索] [方向] [仅异常] [暂停滚动] [清空视图]
时间          方向       阶段/operation              结果
14:23:01.120   WMS→WES    请求已接收                  PAYLOAD ▸
14:23:01.126   WES→WMS    校验完成 / HTTP 422          字段类型错误
选中交互 → [合同差异] [请求 WIRE] [响应 WIRE] [复制诊断信息]
```

以上仅为布局示意，不是运行证据。

## 4. 预期与差异的唯一来源

后端生成比较结果，前端仅渲染，不复制 Pydantic、幂等或业务状态规则。

- 字段结构：使用 operation 所属的现有严格 DTO、parser 和对应响应分支。支持必填、类型、枚举、长度、额外字段、数组元素路径和嵌套字段。
- 响应选择：根据真实 HTTP 状态与合同判别字段选择合法响应联合分支；不能用成功模板检查合法拒绝响应。
- 业务不变量：使用当次业务校验已产生的错误和明确关联的冻结事实，不重新执行业务 handler 或用当前状态重演历史请求。
- 幂等冲突：沿用现有规范化身份与摘要判定；仅在已取得首次冻结内容时展示首次与本次差异，禁止直接用文本差异判定幂等冲突。
- 未知 operation、未匹配合同、截断或未捕获数据：显式标记未校验／信息不足，不显示全量校验通过。
- 示例值仅作为示例；WMS 拥有的业务选择，合同未规定具体值时只对比约束，不虚构唯一预期值。
- 比较结果保存采集时的合同标识、构建版本和规则摘要，查询历史记录不按新版本合同重新判定。

传递现有 ValidationError 的结构化字段路径与错误类型；不能为了诊断改变 parser 的接纳／拒绝结果。复杂联合类型的错误应压缩成可读结论，并保留技术细节展开。

## 5. 采集与存储

第一版采用有界近期诊断记录，复用 Redis 连接能力，由 WMS 诊断 Repository 管理专用 Stream。不是新的业务实体、可靠义务或审计账本；Pub/Sub 不承担历史存储。

每次实际 HTTP 尝试拥有独立诊断 ID。重试保留 operation identity，但新增交互记录；不得只按 operation_id 覆盖上一条。正常响应与已捕获异常均记录；诊断 ID 不能替代公开幂等身份。

保存方向、采集时间、method/path、双方角色、operation identity（可空）、可验证业务关联、传输事实、HTTP 状态、耗时、请求响应的有界脱敏预览、完整性标记、比较结果和版本信息。HTTP 耗时用单调时钟，不将其当作业务完成耗时。

入站复用现有有界读取，覆盖合法请求、非法 JSON、身份无效、不支持 operation、严格 DTO 错误、重复及冲突。采集真实返回的响应。不得扩大业务请求读取上限；过大报文只记录已读大小和安全摘要。

出站由调用 Adapter 的宿主 Service 创建并拥有单次纯技术观察，显式传给 Client、Adapter/parser；Client 补充收发事实，Adapter 补充本次合同校验结论，两者均不保存 Redis。观察在 Adapter 返回或抛出后结束，宿主最多记录一次，再继续原业务结果事务。发送前拒绝标为未发送，不填造响应；尚未取得的后续业务提交状态不得写入观察。Client 不持有 Repository、不解释业务，不在长期复用 Client 上保存单次观察。不得因提取诊断再次发送请求或重读网络流。

入站同样由 Event 调用作用域拥有唯一观察，在实际响应产生后结束一次；前置解析拒绝也归该 owner，保留原提交和 background 顺序。所有观察独立于公开 operation identity，重试保留原业务身份并产生新尝试记录。

取消保持立即传播，不为诊断新增 shield、await 或后台任务；此时 Redis 记录允许缺失。原业务异常保留原异常与 traceback，诊断不能吞掉或替换。

每次尝试以同一 attempt_id 发布最多两类实时观察：`wms_exchange.started` 和 `wms_exchange.completed`。started 仅推送实时事件：出站由 owner 在调用 Adapter 前发布，标为“准备调用”，请求预览来源为宿主冻结内容，不冒充实际发送字节；入站在有界读取后、handler 前发布，标为“请求已接收”。只携带安全取得的预览；completed 在原有唯一结束点产生，携带请求/响应预览、校验摘要、attempt_id 和成功保存时的 exchange_id。只有完成记录进入历史 Stream，仍最多保存一次。前置拒绝或开始通知丢失时允许仅收到 completed，前端可独立创建该行；迟到 started 不得覆盖完成结果。请求/响应/校验日志是这两个结构化事件的呈现，不逐条转发 Python 日志。进程崩溃、记录保存失败或数据过期可能造成记录缺失；页面说明采集边界，不能把没有记录当作没有调用。业务持久化证据仍由原系统保存。

初始配置：保留最近 24 小时且最多 1000 条；每条完整序列化诊断记录最大 32 KiB；每次诊断处理／查询总预算 100 ms。单次调用的诊断阶段按 D2 固定份额分配，不能重置或挤占完成发布份额；只读查询独立使用一次总预算，不拆成发布阶段。全部放在所属能力的单一配置入口，范围与分页硬上限见实施计划。超限优先保留身份、状态与错误摘要，再截断报文和比较项并标注；配置不改变任何业务报文上限。

该预算只累计新增诊断工作，原 HTTP 等待和业务事务不计入；跨业务调用阶段只累计对应阶段耗时，业务等待不消耗诊断份额。预算耗尽不取消业务。采集时尚未取得的业务状态显示未知，不将后续事务尚未执行解释成业务失败。

Repository 必须同时执行数量与时间边界，读取也过滤过期内容，空闲键到期释放；分页以 Stream ID 为稳定游标。单次最多扫描 200 条，累计读取预算 2 MiB、输出预算 256 KiB；预取前按历史记录硬上限 64 KiB 加每条 1 KiB 元数据预留决定批量大小，不能读完整批次再截断。预算耗尽返回基于最后消费项的继续游标及 `scan_incomplete`；已经读取但未消费的记录不得跳过。查询失败明确报错，不伪装空列表。

空 items 但有继续游标时，页面显示本批未匹配并允许继续查询，不宣称整个范围无结果。近期记录模式断开实时连接，不自动遍历所有历史；返回实时模式重新连接并显示连接间隙。第一版保持单 Stream，不预建摘要索引或第二份正文。实施必须以最大记录、稀疏匹配与多查看者验证字节和延迟边界。

失败隔离覆盖观察初始化/补充、schema 展开、比较、脱敏、序列化及 Redis 全链路，不回滚业务、不改变 ACK、不触发新的重试，也不在宿主事务内再打开数据库连接。同步遍历限制深度 32、节点 2048、比较项 256，并检查所属阶段截止时间，不能依赖 asyncio timeout 中断纯同步递归。预算不足则标记诊断不完整；故障降级只用诊断 ID 和安全故障类别，不能再次调用报文转换逻辑。验证须逐阶段注入异常并证明原业务结果与取消行为保持不变。

### SSE 复用与有界传输

后端复用 EventStreamService 的发布/订阅能力，前端复用 authenticatedSseStream 的认证、重连、帧解析与断线提示；不另造 EventSource 管理器。通用 SSE 层只负责传输/资源边界，可独立测试，不能导入 WMS DTO 或业务插件。WMS 诊断层选择自己的频道和严格事件 DTO，负责事件含义及合同比较，业务插件不参与 SSE 运行。

工程评审 D1 已接受：公共订阅的 Redis 异常必须结束当前订阅并关闭对应 SSE 响应，不能把异常转换为正常心跳。仅正常空闲产生心跳；清理订阅资源不得掩盖原异常。前端复用既有 EOF/异常后的重连与间隙提示，不新增数据源恢复状态机。此项属于公共 SSE 语义修正，覆盖所有直接/间接消费者；测试包括订阅建立失败、建立后 Redis 中断、正常空闲、主动取消、恢复后重连和资源释放，不只验证浏览器网络断开。

工程评审 D2 已接受：一次尝试的新增诊断总预算默认 100 ms，固定分为开始观察/预览/started 发布 10 ms、完成结果整理/脱敏/序列化/历史保存 60 ms、最小 completed 摘要构造与发布 30 ms。可配置总预算按 10%/60%/30% 分配，不新增三个独立配置项；未用份额不挪用，任何阶段不得占用完成发布份额。不叠加发布器默认等待时间，不等待浏览器消费。保存超时后用安全的最小摘要发布 completed，exchange_id 为空并注明未保存；摘要只能使用已知安全身份、当次结果与完整性标记，不再次执行失败的完整比较或转换。原业务取消始终立即传播，预留预算不保证 Redis 故障时必达。完成事件不依赖历史保存成功，缺少 exchange_id 时展示实时摘要并注明未保存；任何失败均保持原业务行为。单事件完整 UTF-8 编码上限 32 KiB，请求与响应预览合计最多 16 KiB，先脱敏后截断；更多内容按需读取已保存详情。

沿用 live-only 语义，不承诺 Last-Event-ID 无损回放。重连明确提示间隙，不把未收到 completed 显示为业务失败；历史查询只能补查已保存完成记录。初次连接不自动混入历史；显式切换模式避免初始历史快照与实时订阅竞态。事件以 attempt_id + 阶段去重，历史按 exchange_id 分页。

浏览器同时限制 500 条交互与 2 MiB 序列化事件缓冲，任一超限淘汰最旧项并累计提示；选中详情独立限一条，不无限保留已淘汰报文。新消息批量渲染，慢客户端不积压无界队列；服务端发送阻塞超过 5 秒关闭该连接并由前端提示间隙重连。复用既有服务端连接/心跳机制，若缺少发送超时，仅在公共 SSE 边界补齐通用有界能力并测试，不加入 WMS 逻辑。反向代理关闭该路由响应缓冲并核实空闲超时可容纳心跳。

## 6. 展示 API 与权限

建议后端增加只读接口：

- `GET /api/v1/wms-diagnostics/exchanges/stream`：live-only SSE，静态路径注册在动态详情路径之前；使用 `ops:wms-diagnostics:stream` 只读权限，支持方向/operation/operation_id 筛选。
- `GET /api/v1/wms-diagnostics/exchanges`：有界游标分页，列表仅返回摘要、记录保留范围和采集状态。
- `GET /api/v1/wms-diagnostics/exchanges/{exchange_id}`：当次比较结果、脱敏报文和已保存关联；过期记录返回明确不存在结果。

API → Service → Repository；诊断目录位于宿主 `src/app/wms_diagnostics/`，不往 SDK 或业务插件加入 UI/存储概念，不增加生产 operation registry。

列表、详情、实时订阅分别校验 `ops:wms-diagnostics:query`、`ops:wms-diagnostics:read`、`ops:wms-diagnostics:stream`。遵循现有一个权限码对应一个 API 路径的目录合同，前端仍展示一个菜单，各模式与详情按各自权限启用。复用现有账号和角色，工程人员按权限访问；不能要求 WMS 人员持有超级管理员权限。前端现有 ops 父路由有超级管理员限制，实施时必须核实父子权限合并机制，仅为此页面提供正确可达性，保留其他运维页面的原访问边界。

不保存 Authorization、Cookie、密码或凭据；headers 使用必要字段白名单，正文先脱敏再存储。非法 JSON 不可安全识别敏感字段时省略正文并说明原因，不能未经处理直接保存。复制功能复用详情数据，不绕过权限或脱敏。

前后端合同遵循仓库现有 OpenAPI 与权限生成流程。后端完成验证并进入可冻结基线后再冻结前端 canonical；不得把 dirty 后端假装为已合入 develop 的合同。

## 7. 实施边界与验证

本任务为共享收发路径的高风险变更，实施前按 AGENTS.md 冻结生产符号、调用点、共享消费者、测试 owner、HEAVY mapping 和环境快照。GitNexus 影响分析发现的新范围须报告；批准产品范围不能代替尚未分析的风险确认。

后端验证重点：

- 每个正式 operation 的采集覆盖清单和所选请求／响应 DTO 来源。
- 入站合法、非法、重复、冲突；出站合法响应、合法业务拒绝、错误类型、非法 JSON、超时及取消。
- 诊断开启／故障时，原响应、Evidence、幂等、重试、单次发送与事务语义保持一致。
- 实际 API 与 worker 进程均可写入并由 API 查询；不能仅用单进程假对象证明多进程共享。
- 保留期、数量、序列化大小、总预算、分页字节和脱敏边界；记录缺失不得展示通过。覆盖最大记录、稀疏筛选和 近期记录查询正常隔离环境 p95 ≤ 100 ms 且无超时；另验证 10 个 SSE 查看者、每秒 10 次交互持续 60 秒，正常局域网完成事件到达浏览器 p95 ≤ 500 ms，缓冲不越界。
- 每个行为只有一个主要测试 owner，operation 测试仅证明接入差异；HEAVY 按实际 mapping selector 执行。

前端验证重点：字段差异及只看异常、正确联合分支、无响应与截断、过期详情、API 故障、权限、连接取消和复制结果；增加采集时状态文案、后台业务变化不改写快照、预算耗尽分页、断线间隙、孤立完成事件、去重、暂停滚动、清空视图和缓冲淘汰；完成真实浏览器 QA。

成功标准：双方可以通过 operation_id 或任务关联找到近期交互，在详情直接读到预期规则、实际字段和具体异常；合法拒绝不误报合同错误；诊断失败不改变业务结果。

实施前重新检查当前仓库与共享路径的工作状态；需要隔离时使用独立 worktree 和运行环境，保留其他任务现场。设计与计划原位更新并作为当前真源，文档本身仅做结构、引用和 diff 检查，不运行代码测试。
